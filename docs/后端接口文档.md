## 1. 全局约定

### 1.1 网络层

| 项 | 值 | 说明 |
|---|---|---|
| 前端 axios baseURL | `/api` | 两个项目**一致** |
| 请求超时 | `10000` ms | 上传大图需注意 |
| 开发代理目标 | `http://8.211.173.225:666` | 两端 vite 相同 |
| 路径重写规则 | `path.replace(/^\/api/, '')` | **后端不接收 `/api` 前缀** |
| 管理端开发端口 | `5174` | user-web 未指定，用 vite 默认 5173 |
| 静态资源代理 | `/uploads` → 同一后端 | 上传文件必须能通过 `/uploads/**` 直接访问 |

**三层 URL 对应关系（重要）**

| 层次 | 示例 |
|---|---|
| 前端代码书写 | `request.post('/user/login')` |
| 浏览器实际发出 | `POST http://localhost:5173/api/user/login` |
| 后端收到（经代理剥离） | `POST /user/login` |
| 生产环境建议 | Nginx 将 `/api/` 反代到后端 `/`；或后端设 `server.servlet.context-path: /api` 后调整代理 |

> 重写时**两种方案任选其一**，但必须与前端 `vite.config.js` 的 rewrite 规则保持一致，否则所有请求 404。

### 1.2 统一响应包装

前端拦截器 `res => res.data` 直接返回响应体，各页面统一判 `res.code === 200`，故约定：

| 字段 | 类型 | 必填 | 含义 | 示例 |
|---|---|---|---|---|
| `code` | `int` | 是 | 业务状态码，**200 = 成功** | `200` |
| `msg` | `string` | 否 | 提示文案，失败时前端**直接弹窗展示** | `"用户名或密码错误"` |
| `data` | `T`（泛型） | 否 | 业务数据，成功时可为 `null` | `{ "token": "...", "uid": 12 }` |

```json
{ "code": 200, "msg": "success", "data": { "token": "eyJhbGci...", "uid": 12 } }
```

**硬性约束（违反则前端报错）**

1. `code` 必须是**数字类型**，前端使用 `===` 严格比较；返回字符串 `"200"` 会导致登录被判定为失败。
2. 失败时 `msg` 必须为可直接展示给用户的中文文案（前端 `ElMessage.error(err.response?.data?.msg || '请求失败')`）。
3. **鉴权失败必须返回 HTTP 状态码 401**，而不是 HTTP 200 + `code:401`。原因：拦截器在 `error` 分支里判 `err.response.status === 401`，只有 HTTP 401 才触发「请先登录 + 跳登录页」。
4. 数组型 `data` 直接返回 JSON 数组，当前**无任何分页包装对象**（见 1.4）。

### 1.3 鉴权

| 项 | 约定 |
|---|---|
| 传输方式 | 请求头 `Authorization` |
| 值格式 | `Bearer <token>`（注意 Bearer 后有 1 个空格） |
| 前端存储 | `localStorage.setItem('token', token)` |
| token 生成 | 登录接口返回 `data.token`；前端不解析其内容，只回传 → 推荐 JWT（HS256），载荷含 `uid` |
| 有效期 | 前端不处理过期，唯一依赖是 401 拦截 → 建议 2h，不做 refresh token |
| 登出 | **无后端接口**，纯前端清除 localStorage |
| 免鉴权白名单 | `/user/login`、`/user/reg`、`/user/regions/**`、`/user/getMajor`、`/home/**`；`/BBS/**` 读接口当前也由前端守卫控制，建议后端对写操作强校验 |

**鉴权漏洞提示（现状缺陷，重写时修）**

- `ZSB-admin-web` 的 store 把 token 存进 `admin_token`，但 `request.js` 读的是 `token` → **管理端所有请求均不带 Authorization 头**。
- 管理端 `isAdmin` 判 `userInfo.ustate === 3`，但该字段从未被赋值 → 恒为 `false`，路由守卫形同虚设。

### 1.4 分页

**现状：全站无分页。** 20 个接口均返回全量数组，前端一次性渲染（学校列表、政策列表、帖子列表、收藏列表均无页码/无 `total`）。

| 项 | 现状 | 建议 |
|---|---|---|
| 分页参数 | 无 | 新增 `pageNum`（默认 1）、`pageSize`（默认 10，上限 100） |
| 分页响应 | 无包装 | `data: { list, total, pageNum, pageSize }` |
| 兼容策略 | — | 保留旧路径返回数组，新路径 `/api/v1/**` 返回分页对象；或分页对象增加 `data` 数组别名 |

> 重写阶段建议**先按现状返回数组**跑通联调，再逐步加分页，避免前端大改。

### 1.5 文件上传与下载

| 项 | 现状 |
|---|---|
| 上传接口 | 仅 `POST /BBS/insert`，`Content-Type: multipart/form-data` |
| 上传字段名 | 图片字段固定为 `image` |
| 前端体积校验 | 帖子图片 ≤ 5MB；注册头像 ≤ 2MB（且前端压缩到 200px 后**实际未上传**，见 Q3） |
| 允许类型 | `image/*`（前端只校验 MIME 前缀） |
| 存储路径 | 返回相对路径，如 `/uploads/2026/11/xxx.jpg`；前端对相对路径自动补前导 `/` |
| 访问方式 | 开发代理 `/uploads` → 后端；生产需 Nginx/静态资源映射 `/uploads/**` |
| 下载 | **无下载接口** |

**建议**：后端校验真实 MIME（`Files.probeContentType`）+ 扩展名白名单（jpg/png/webp/gif）+ 重命名 UUID + 按 `yyyy/MM` 分目录；单文件上限 5MB。

### 1.6 日期时间格式

| 项 | 约定 |
|---|---|
| 传输格式 | 字符串，**已格式化好**，`yyyy-MM-dd HH:mm:ss` |
| 证据 | 前端 `{{ item.post_time }}`、`{{ item.create_time }}` 直接输出，**无任何 dayjs/moment 处理**；管理端表格列宽 `170px`（恰好容纳 19 字符） |
| 时区 | `Asia/Shanghai`（GMT+8） |
| 仅日期字段 | `year` 为纯整数年份（如 `2026`），非日期字符串 |

**约束**：后端必须用 `@JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss", timezone = "GMT+8")` 输出，**不能返回时间戳或 ISO8601**（`2026-11-03T16:08:48` 会原样显示带 T，前端不会处理）。建议 DB 用 `DATETIME`。

### 1.8 错误码

| HTTP 状态 | `code` | 场景 | 前端行为 |
|---|---|---|---|
| 200 | 200 | 成功 | 正常渲染 |
| 200 | 非 200 | 业务失败（如用户名已存在） | 页面 `throw new Error(res.msg)` → 弹 `msg` |
| **401** | 401 | token 缺失/过期/非法 | 弹「请先登录」+ 跳 `/login` |
| 400 | 400 | 参数校验失败 | 弹 `msg` |
| 403 | 403 | 无权限（管理端接口） | 弹 `msg` |
| 404 | 404 | 资源不存在 | 弹 `msg` |
| 413 | 413 | 上传超限 | 弹 `msg` |
| 500 | 500 | 服务端异常 | 弹 `msg`（勿返回堆栈） |

**建议业务码空间**（现状未区分，重写可扩展）：

| 区间 | 用途 |
|---|---|
| 40001~40099 | 参数校验 |
| 40101~40199 | 认证（40101 用户名或密码错误、40102 token 过期、40103 账号禁用） |
| 40301~40399 | 权限 |
| 40401~40499 | 资源不存在（40401 用户不存在、40402 帖子不存在、40403 院校不存在） |
| 40901~40999 | 冲突（40901 用户名已注册、40902 手机号已注册、40903 重复点赞、40904 重复收藏） |

**幂等要求**：`like_post` / `add_favorite` 重复调用**不得报错**（前端做乐观更新且异常时会回滚 UI，若后端返回 409 会误触发回滚提示）。

## 3. 登录认证模块

### A-01 登录

| 项 | 内容 |
|---|---|
| 用途 | 用户名密码登录，返回 JWT 与用户 ID |
| 方法 / 路径 | `POST /user/login`（前端 `POST /api/user/login`） |
| 前端入口 | 用户端登录页「登 录」按钮；管理端登录页（**当前走前端硬编码，见 Q1**） |
| Content-Type | `application/json` |
| 鉴权 | 否 |

**请求体**

| 字段 | 类型 | 必填 | 含义 | 示例 |
|---|---|---|---|---|
| `uname` | string | 是 | 用户名（登录页校验 3~20 位，字母/数字/下划线/中文） | `"zhangsan"` |
| `pwd` | string | 是 | 密码明文（HTTPS 传输；前端不做加密） | `"abc123456"` |

> 前端映射：`login({ uname: form.username, pwd: form.password })`。

**成功响应** `data`：见 DTO `LoginVO`

| 字段 | 类型 | 含义 | 示例 |
|---|---|---|---|
| `token` | string | JWT 字符串，**不含 `Bearer ` 前缀**（前端自行拼接） | `"eyJhbGciOiJIUzI1NiJ9..."` |
| `uid` | long | 用户 ID，前端落 localStorage 供后续 `/user/info/{uid}` 使用 | `12` |

```json
{ "code": 200, "msg": "登录成功", "data": { "token": "eyJhbGciOi...", "uid": 12 } }
```

**失败场景**

| 场景 | HTTP | `msg` 示例 | 前端表现 |
|---|---|---|---|
| 用户不存在 / 密码错误 | 200 + `code:40xxx` 或 401 | `"用户名或密码错误"` | store `throw new Error(res.msg)` → 登录页弹错 |
| 参数为空 | 400 | `"用户名不能为空"` | 同上 |
| 账号被禁用（建议） | 200 + `code` 非 200 | `"账号已被禁用"` | 同上 |

> 注意：登录失败**不要**返回 HTTP 401，否则会被拦截器跳转到 `/login` 并提示「请先登录」，而不是「用户名或密码错误」，体验错乱。

**后续链路**（后端无需关心，但影响契约）：登录成功后前端立刻发 `GET /user/info/{uid}`，若该接口失败则整个登录流程抛错但仍已写入 token。建议 `/user/info` 保持稳定。

| `year` | int | 是 | 报考年份，前端从「当前年 ~ +4」生成 | `2027` | 纯数字年份 |
| `regions` | int | 是 | 地区 ID，取级联选择器**数组最后一个元素**（最细一级） | `1301` | 字段名复数但是标量，见 Q4 |
| `phone` | **number** | 是 | 手机号，`^1[3-9]\d{9}$`，前端 `Number()` 转换 | `13800138000` | 超出 int32 范围，见 Q5 |

```json
{
  "uname": "zhangsan", "pwd": "abc123456", "nickname": "zhangsan",
  "avatar": "", "major": 3, "year": 2027, "regions": 1301, "phone": 13800138000
}
```

**成功响应**：`data` 无约定（前端不读），返回 `null` 即可，仅需 `code: 200`。失败时前端弹 `msg` 并停留当前页。

**失败场景**

| 场景 | 处理 |
|---|---|
| 用户名已存在 | `code` 非 200，`msg: "用户名已注册"` |
| 手机号已注册（建议） | `code` 非 200，`msg: "手机号已被注册"` |
| 专业 ID / 地区 ID 不存在 | `code` 非 200，`msg: "所选专业不存在"` |
| 字段校验失败 | HTTP 400 或 `code` 非 200 + 中文 `msg` |

> 前端校验通过不代表数据合法（可绕过），后端必须重复校验：`uname` 长度/字符集/唯一、`pwd` 长度、`phone` 正则、`year` 合理区间、`major`/`regions` 外键存在性。

### 8.3 互动（点赞 / 收藏）

> 以下 6 个接口**全部无请求体**，参数只在路径上，且**必须幂等**。前端采用乐观更新：先改 UI 再发请求，请求异常则回滚并弹「操作失败」。因此后端返回非 2xx 会造成 UI 闪烁。

| 编号 | 用途 | 方法 / 路径 | 路径参数 |
|---|---|---|---|
| H-01 | 帖子点赞 | `POST /BBS/like_post/{uid}/{postId}` | `uid`(int) 用户 ID；`postId`(int) 帖子 ID |
| H-02 | 取消帖子点赞 | `POST /BBS/unlike_post/{uid}/{postId}` | 同上 |
| H-03 | 评论点赞 | `POST /BBS/like_comment/{uid}/{commentId}` | `uid`(int) 用户 ID；`commentId`(int) 评论 ID |
| H-04 | 取消评论点赞 | `POST /BBS/unlike_comment/{uid}/{commentId}` | 同上 |
| H-05 | 添加收藏 | `POST /BBS/add_favorite/{uid}/{targetType}/{targetId}` | `uid`(int)；`targetType`(int)：`1` 帖子 `2` 政策；`targetId`(int) |
| H-06 | 取消收藏 | `POST /BBS/clear_favorite/{uid}/{targetType}/{targetId}` | 同上 |

**示例**：`POST /api/BBS/like_post/12/9001`

**成功响应**：`data` 前端不读。**建议返回最新计数**，便于前端后续校准：

| 字段 | 类型 | 含义 |
|---|---|---|
| `like_count` / `fav_count` | int | 操作后的最新总数 |
| `is_liked` / `is_fav` | int | 操作后的状态 `1`/`0` |

**行为约定**

| 场景 | 期望 |
|---|---|
| 重复点赞 | 返回 `code:200`（幂等，不报 409） |
| 取消未点赞的记录 | 返回 `code:200` |
| `targetType` 非 1/2 | 400，`msg: "收藏类型非法"` |
| 目标帖子/评论/政策不存在 | `code` 非 200，`msg: "内容不存在或已删除"` |
| `uid` 与 token 不一致 | 建议 403（当前前端不校验，存在刷赞风险） |

**唯一性约束（DB 层）**：`(user_id, post_id)`、`(user_id, comment_id)`、`(user_id, target_type, target_id)` 建唯一索引，配合 `INSERT IGNORE` / `ON DUPLICATE KEY` 实现幂等。

## 10. 两项目差异与合并建议

### 10.1 接口层差异

| 项 | ZSB-user-web | ZSB-admin-web | 结论 |
|---|---|---|---|
| axios 封装 | `baseURL /api`、拦截器、401 处理 | **逐字相同** | 无需区分，同一套后端 |
| API 文件组织 | 5 个文件按业务拆分 | 3 个文件，`user.js` 里混装院校/政策/地区 | 仅前端组织差异，接口一致 |
| 同一接口重复定义 | `getRegions` 在 `api/user.js` 与 `api/consult.js` **各定义一次** | `getRegions` 在 `api/user.js` | 路径完全相同，后端只需 1 个实现 |
| `getPolicies` 归属 | 独立 `api/consult.js` | 塞在 `api/user.js` | 同上 |
| bbs API 能力 | 10 个（含点赞/收藏/发帖） | 3 个（仅读） | 后端能力以用户端为准 |

**结论**：两端**没有路径冲突**，是同一后端的两个消费方。唯一需要统一的不是接口，而是**鉴权实现**。

### 10.2 鉴权冲突（必须解决）

| 冲突点 | 用户端 | 管理端 | 后果 | 合并建议 |
|---|---|---|---|---|
| token 存储 key | `token` | `admin_token` | 管理端所有请求**不带 Authorization 头** | 统一为 `token`；如确需隔离，则 `request.js` 读 `token \|\| admin_token` |
| 登录实现 | 真调 `POST /user/login` | **前端硬编码 `admin/admin123`**，`uid=0`，token 为字符串 `admin_mock_token` | 管理端登录与后端完全脱节；伪造 token 可进后台 | 统一走 `POST /user/login`，后端校验 `ustate=3`；非管理员返回 `code` 非 200 + `msg:"仅管理员可登录"` |
| 管理员判定 | `userInfo.role === 'admin'`（但 store 硬编码 `role:'student'`） | `userInfo.ustate === 3`（但从未赋值） | 两端 `isAdmin` **恒为 false** | 统一用 `ustate`：`0` 学生 / `3` 管理员；`/user/info` 必须返回 `ustate` |
| 路由守卫 | 读 `token` | 读 `admin_token` | 守卫可被 `localStorage` 手改绕过 | 前端改 key 统一；**后端对所有写接口做服务端鉴权**（前端守卫不是安全边界） |
| 管理员 uid | — | 硬编码 `0` | 管理端 `getPostDetail(0, id)` 恰好利用了 `uid=0` 匿名语义 | 保留 `uid=0` 支持，但真实管理员应传自己 uid |

### 10.3 字段命名冲突（响应体）

| 实体 | 用户端读法 | 管理端读法 | 建议统一 |
|---|---|---|---|
| 院校校徽 | 首页 `school_logo \|\| logo`；院校页 `logo_url`；搜索页 `school_logo`；计划详情 `school_logo` | `logo_url` | **同时返回 `logo_url` 与 `school_logo`**（同值），删除 `logo` |
| 院校名称 | 首页 `school_name \|\| name` | `school_name` | 只返 `school_name` |
| 院校类型 | 首页 `school_type \|\| type` | 未使用 | 只返 `school_type`（Integer） |
| 政策类别 | 请求 `type`，响应 `category_id` | 同 | **请求/响应都叫 `category_id`**（或都叫 `type`），二选一；过渡期请求侧两个名字都接受 |
| 帖子时间 vs 政策时间 | `post_time` vs `create_time` | 同 | 保留现状（不同表不同字段），但在 DTO 注释中明确 |
| 评论时间 | `create_time` | 未用 | 保留 |

| 安全 | `module` 白名单 `[a-z]{2,12}`，非法值落 `common`；落盘路径做 `startsWith` 越界校验 |
| 响应 | `{"code":200,"data":"/uploads/school/2026/11/xxx.png"}` |
| 用途 | 院校校徽、政策配图，避免让运营手填图片地址 |

### 14.3 政策详情带收藏状态

`GET /home/getPolicies/{id}?uid={uid}`

- 新增可选参数 `uid`；不传按 0（游客）处理。
- 响应体新增 `is_fav`（0/1），前端收藏按钮初始状态不再需要额外请求收藏夹。
- 浏览量照旧 +1。

### 14.4 帖子列表新增作者字段

`GET /BBS/info/{provinceId}/{schoolId}`、`GET /BBS/myPosts`、`GET /admin/post/list` 的每条记录新增：

| 字段 | 类型 | 说明 |
|---|---|---|
| `nickname` | string | 作者昵称（JOIN `user` 带出） |
| `avatar` | string | 作者头像地址 |

不改变原有字段，前端可平滑使用。

### 14.5 管理端新增页面（复用已有接口）

## 15. 首页展示相关（本轮新增）

### 15.1 最新讨论

| 项 | 内容 |
|---|---|
| 方法/路径 | `GET /BBS/latest?limit=6` |
| 鉴权 | 免登录（游客可访问） |
| 参数 | `limit` 可选，默认 6，服务端强制限制在 1~20，防止一次拉全表 |
| 响应 | `{"code":200,"msg":"success","data":[Post...]}`，按 `post_time` 倒序 |
| 字段 | 同帖子列表：`id / content / region_id / school_id / view_count / like_count / post_count / post_time / nickname / avatar` |
| 用途 | 首页「最新讨论」板块，跨省份聚合，不受用户当前所选地区影响 |

### 15.2 论坛读接口对游客开放

| 接口 | 变更 |
|---|---|
| `GET /BBS/info/{provinceId}/{schoolId}` | 原本免登录 |
| `GET /BBS/latest` | 新增，免登录 |
| `GET /BBS/GetPostDetail/{uid}/{postId}` | **改为免登录**（`uid` 传 0 即游客，不返回 `is_liked`/`is_fav`） |
| `GET /BBS/comments/{uid}/{postId}` | **改为免登录**（同上） |
| `POST /BBS/comments`、`POST /BBS/like_post/**`、`POST /BBS/add_favorite/**` | 仍需登录，游客访问返回 **HTTP 401** |

前端配套：`/bbs`、`/bbs/:id` 路由不再要求登录；游客点击「发帖 / 点赞 / 收藏 / 评论」时提示先登录并带上 `redirect` 回跳。
